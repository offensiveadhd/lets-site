Defaults vs the store

Two lists, two jobs.

✦defaults.json

The list of uniques every installation gets, kept in the engine repo. The engine clones them into ~/.lets/uniques the first time it runs, or the first time you open one. Today that list is graph. Defaults are trusted by the list and still validated before they are served; LETS_NO_DEFAULTS=1 opts out.

⌂The store

Where community uniques live. lets-store is a git repository whose index.json points at uniques by git URL. Install with /lets store <name>: you see the permissions and the verified flag, and nothing installs until you say yes.

What "verified" means →

New candidates grow in the store first; once a unique is solid it can be proposed for defaults.json.

Propose a unique

Built something? Validate it with node engine/bin/lets.mjs validate, then open a pull request to lets-store adding your entry to index.json. A maintainer reviews the manifest and marks it verified.
