lets

Talk to Claude through windows, not just text.

lets is an engine for Claude Code. A zero-dependency Node MCP server that hosts interactive windows, called uniques, beside your chat: it serves them, carries one small protocol between you and Claude, keeps the companion's memory, saves what you send, installs more uniques from git, and runs your programs on your machine. Doto, a small bright dot, rolls along in every window.

Two uniques show what it can do: graph, a board you talk through in diagrams, and cocode, an editor where Claude predicts your next lines, builds the real program and runs it.

The engine

One engine, any window

The engine knows nothing about graphs or code. It hosts a unique (a static web app with a manifest and a guide for Claude), gives it the companion, chat and components for free, and carries everything that happens across one protocol, LIP: typed JSON envelopes, up (you → Claude) and down (Claude → window). A unique for voice, AR or a haptic strip would speak the same envelope.

Hosts windows

A zero-dependency Node MCP server. It serves uniques on loopback, behind a per-host token and a strict CSP, in the app's browser pane or your system browser. No npm install, no build step, no admin rights; everything it keeps lives under ~/.lets.

One protocol

LIP: what you do in the window reaches Claude as meaning (a node you added, a line you asked about), never as pointer moves. Claude answers with commands the window animates. Each unique declares its own events, commands and permissions in a manifest.

A companion

Doto, Claude's presence in every window: a dot that rolls after your cursor, points, pitches in, and learns how you work. What he learns is written to disk where you can read it, and /lets den lets you edit or forget any of it.

Meet Doto →

Saved sessions

Send to Claude is a handoff: the engine saves the window's content, the window says goodbye and closes, and Claude answers in your chat. Say continue or /lets graph resume and the window comes back as you left it.

A store

More uniques come from git. /lets store cocode syncs the community store, shows you the manifest, its permissions and the verified flag, and installs into ~/.lets/uniques only after you say yes. Two defaults come with the engine itself.

A runner and native panes 0.7.0

A unique that holds a program can run it on your machine after one consent: Python under an audit hook, JavaScript and TypeScript under Node's permission model, output back in milliseconds. And a unique with a native view opens as a pane inside Claude Code, with no browser at all.

cocode from the store

Talk in code. An editor for any language, even one that doesn't exist. Claude predicts your next lines as a ghost you accept with Tab, prepares the real program while you type, and runs it on your machine the moment you press F5.

  • Your pseudo-code stays yours. The real Python or JavaScript lives in the Build pane, and Run executes it in milliseconds after one consent.
  • A line starting with ?? is a question. A line like ping google.com or research … is a reach: Claude does it for real with his own tools.
  • Send to Claude hands the code over as a question, a task, a fix or a note; Answer in code brings the reply back as code.
/lets store cocode   # inspect, then say yes
/lets cocode         # open it

How it feels

Point at things instead of typing them

  1. Open a window

    /lets graph plan the auth flow or /lets cocode. Claude opens the unique in the app's browser pane, seeds a start, and Doto says hi.

  2. Draw, type & chat

    Add nodes, accept a ghost line, right-click for Doto, chat on the side. Everything you do reaches Claude as meaning, with your next message or at once.

  3. Send to Claude

    The window says goodbye and closes itself; Claude reviews the board or the code right in your Claude Code chat.

  4. Say "continue"

    "Continue the auth board" or /lets graph resume brings the window back as you sent it, and Claude draws in its proposals.

The companion

Meet Doto

Doto is a dot that does: Claude's presence inside the window. He rolls after your cursor on a gentle spring, flips sides so he never covers what you point at, and gets sleepy when you pause. Claude sets his mood: thinking while it works, proud when it's done, curious when it asks.

He talks short: verb first, one line, ending on a dot. "On it." "Done. Look." He keeps count, too: boops in a row, secrets found. And he learns how you work (your pace, your clicks, what you liked) and writes it down where you can read it, in ~/.lets/entity/. Nothing is learned silently. You can rename him, too.

Expressions

Doto reacts to how you move: shake the mouse and he gets dizzy, a click storm startles him, an undo gets an "oops", lingering on him makes him blush. It all runs in the window: zero tokens, short, never in your way, and calm when you prefer reduced motion.

Install

Install the engine

Paste one line into Claude Code and let it do the setup. It clones the repo, runs the installer and follows the repo's INSTALL.md. The engine brings graph and den with it; cocode and mors are one store command away.

The install prompt

Install the `lets` plugin for Claude Code on this machine: clone https://github.com/offensiveadhd/lets (`git clone https://github.com/offensiveadhd/lets.git`), then run `node install.mjs` inside the clone and follow INSTALL.md in that repo. When done, tell me to restart Claude Code and show me `/lets graph`.

The repositories are public: no GitHub login is needed to clone or install. Contributions are welcome.

Or by hand

Needs Node 18+, the claude CLI on your PATH, and git.

git clone https://github.com/offensiveadhd/lets.git
cd lets
node install.mjs

Restart Claude Code (or run /reload-plugins), then:

/lets graph

Prefer the plugin manager? Inside Claude Code: /plugin marketplace add offensiveadhd/lets then /plugin install lets@lets. All the options are in Getting started.
