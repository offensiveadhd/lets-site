Talk in code (cocode) new

Type in any language, even one that doesn't exist. Claude predicts your next lines, prepares the real program while you type so Run is instant, and reads what you send as a message written in code. cocode lives in the store: it is not a default.

What it is

You type in any language: a real one, one you made up, or plain pseudo-code. The window never judges it. Three things happen around what you type:

  1. Prediction. Claude reads each settled change and offers the next lines as a ghost: dim, italic, slightly blurred text at the caret. It is not in the document until you press Tab. When Claude is away, a small local predictor offers weaker ghosts, so the page still feels alive.
  2. The build. While you type, Claude prepares the real program (Python, JavaScript, …) for the current revision and puts it in the Build pane. Run then executes that build at once instead of starting from zero, and the output streams into the Output pane.
  3. Talking in code. Ask and Send to Claude carry the code as the message. Claude works out what you mean with it (a question, something to explain, something to do, a bug, a note) and answers in that register.

An empty editor shows seeds: starting points Claude draws from memory and your saved sessions. cocode stores nothing on the host. The document lives in the window, and in a saved session after Send to Claude.

Install

cocode is not in the engine's defaults.json. It lives in lets-store, so you install it once:

/lets store cocode      # inspect → confirm
/lets cocode            # open it

Claude shows you the inspection (permissions, problems, the verified flag) and copies it into ~/.lets/uniques/cocode only after you say yes. Manual: clone the repo into ~/.lets/uniques/cocode.

cocode needs engine 0.4.0 or later ("engine": ">=0.4.0") for handoff sessions; it needs no new engine endpoint. It asks for no permissions: "fs.write": [], "net": []. The window writes nothing and runs nothing itself: Claude runs your program with its own tools (below).

This page describes cocode 0.1.0 (2026-10-13). Like the other lets repositories, its repository is private for now.

An empty page. An empty editor says "Type in any language. Even one that doesn't exist." and shows a start from list: Claude's seeds first, then your recent code from this browser. Each one is a button with a label, a language badge and a two-line preview; picking one fills the editor. Esc or typing hides the list. When the window opens empty, Claude sends two to four seeds drawn from your saved sessions ("Continue user welcome script"), Doto's special skills and what the project is about, and Doto says "Empty page. Start anywhere."

What stays in the browser. Your text, language and pane state are kept in sessionStorage for this tab, so a reload keeps the code. localStorage keeps preferences (rail open or closed, font size, wrap) and your last 10 recents, recorded on Run and on Send. Nothing else is stored. Without a host, the editor still works locally; Run, Ask and Send are off.

Doto on this page. He sits by the caret. Click him for Finish this, Explain this line (or Explain the selection), Run it, Show the real code and Open chat. He reacts once per thing you do, at most: a wink when you accept a ghost, a nod when a build lands ready, a cheer when a run exits 0 and when you send to Claude, an oops when a run fails, and a sparkle when you accept three ghosts in a row.

The ghost

The prediction loop, step by step:

  1. You type. After 500 ms of quiet, the window sends the settled text to Claude (cocode.changed), with the caret line so far (prefix).
  2. Meanwhile, after 250 ms, the local predictor may already show a weak ghost, labelled local in the status line.
  3. Claude answers with one ghost for that revision (cocode.suggest): the next one to four lines, in your dialect. It replaces the local one. If the caret is mid-line, the ghost starts with the rest of that line. Two or three alternatives come along when the fork is real (else or return).
  4. Typing the characters the ghost starts with shrinks it instead of dismissing it. Any other key dismisses it, and so do moving the caret and Esc. Tab accepts all of it (the first line's indentation follows your current line); Ctrl+→ accepts one word.

There is never more than one ghost on screen, and the window shows at most 12 lines of it. A ghost Claude made for an older revision shows only while the text before the caret still matches what you had typed then; otherwise it is dropped without a word. An accepted ghost is your change: rev goes up and Claude sees it like anything you typed.

When Claude is away

The local predictor (ui/predict.js) keeps the page alive with weaker ghosts of at most two lines. It is synchronous and fast (under 2 ms for 64 KB), and the first rule that fits wins:

RuleWhenOffers
ClosersA (, [ or { on the caret line is not closedThe missing closers, plus : after a Python def, if or for line head
PairsThe previous block opened with if, try, for or while (python, pseudo) and the caret is on a fresh line at the block's indentationelse:, except Exception as e:, or nothing for loops. JS-like code gets } else { and } catch (e) {.
SequencesTwo or more previous lines differ only in a number or a letter (step 1, step 2)The next one
EchoThe caret line (3 characters or more) is the start of an earlier, longer lineThe rest of that line
Repeat shapeThe two previous lines start with the same bullet marker (-, *, •, >) or with consecutive numbers (1., 2.)That marker, or the next number

Accept, dismiss, and what Claude learns

Every accept and dismiss goes to Claude as feedback: cocode.ghost.accept (with partial: true for one word) and cocode.ghost.reject with the reason (esc, typed-away, moved). Claude reads them plainly. Three rejects in a row mean shorter, more literal ghosts. A partial accept means the first word was right. A dismissed ghost is a "no", so Claude does not send it again for the same revision. Once per session at most, Claude writes a style note into Doto's memory, such as "writes python-ish pseudo-code, 2-space indents, accepts short ghosts". The window counts accepts and rejects in stats.

Build ahead & Run

While you type, Claude keeps a real, runnable version of your code in the Build pane (cocode.build). The language is your target if you picked one in the Build pane, or the chip's language if it names a real one; pseudo-code becomes Python unless your dialect is clearly JS-like. The build is self-contained: sample data where input is implied, prints for what the program computes, nothing interactive, no network, no writes outside the working folder.

Claude waits until the purpose is clear and the text is more than a line or two, and while you type fast it builds every few revisions. The pane shows the language, the rev and the status: a spinner while building, the reason when it failed. When you type past it, the status reads stale for rev N in dim text, and the code stays until a new build arrives.

Run (Ctrl+Enter) opens a new entry at the top of the Output pane and sends cocode.run with the latest build attached, stale or not. Then Claude:

  1. runs that build if it matches the current revision; otherwise it builds for this revision first (you see a dim "building first…" line), then runs;
  2. writes the file into its scratch folder and runs it with its own tools: 30 s timeout, no network, no sudo, no deletes. If the program would touch files outside that folder or needs secrets, Claude stops and asks one short question in the chat;
  3. streams stdout and stderr into the entry, and always closes it with the exit code and the time it took;
  4. says one Doto line: "Ran it. Exit 0, 3 lines." or "Failed on line 4. See Output." If it failed because your intent was unclear, Claude says what it assumed and offers the fix as a ghost or a note on the line, not a rewrite.

If the host is not connected, Run shows a toast and does nothing. If Claude is away, the entry still opens and a toast says "Doto is away. The run starts with your next message in Claude Code." (at most once every 30 seconds). A run with no output for 60 seconds shows no answer yet (status lost) until output arrives.

Talking in code

In cocode, the code is the message. There are three ways to talk:

  • Ask (Ctrl+K, or a question from Doto's menu): a one-line question about the current line or the selection. Claude answers in the chat in two to eight lines, highlights the lines it talks about and clears the glow when done. If the question asks for a change, Claude makes it with an insert or a replace, then says one line.
  • A ?? line: type ?? why is this slow in your code and press Enter. It goes to Claude as a question, like asking the person next to you. The line stays in the document as your note; Claude answers in the chat and pins a one-line reply to that line.
  • Send to Claude: the whole document as a handoff (next section).

The six intents

The intent select next to Send to Claude says how to read the code. Leave it on you decide and Claude reads the code as a message: ?? lines and comments are questions or asides; imperative lines ("deploy this", "make it faster") and TODOs are a task; a stack trace, a failing run or a fix line is a bug; a complete program is a review, or "does this do what I think?"; prose in code clothes is a note. Claude says in one line which reading it chose, then answers in that register:

Send to Claude & resume

Send to Claude is a handoff. The window sends cocode.export: your code, its language, the caret and selection, the latest build, the last three runs (output tails of 2,000 characters), the notes and the ghost stats. The engine saves it as a session and closes the window, with a cheer from Doto. Claude answers in the Claude Code chat, not in the window.

The window names the session after your first non-empty line and the language, such as for each user in users · pseudo; Claude then labels it in three to six words. Say continue (or /lets cocode resume) and the window comes back with cocode.load: your text, language, build, runs, notes and caret, with no ghost or accept events. Claude carries on with ghosts and builds. If the tab also kept a draft, a load in the first 8 seconds wins over it.

The manifest's session block names the roles:

"session": { "export": "cocode.export", "snapshot": "cocode.snapshot", "restore": "cocode.load" }

Events (up)

Each event says what you meant. Lines are 1-based, columns 0-based. In every event, text is at most 64,000 characters; longer text keeps the tail and carries truncated: true.

EventWhen
cocode.changed {rev, text, lang, detected, cursor, selection, lines, prefix, by, delta?}The text settled, 500 ms after the last keystroke: you typed, pasted, accepted a ghost or undid, or a command from Claude changed the text. by is "human", "claude" or "restore". prefix is the caret line up to the caret (at most 200 characters). delta {from, to, text} is the changed line range when known.
cocode.ghost.accept {rev, source, text, partial}You pressed Tab (the whole ghost) or Ctrl+→ (partial: true, one word). source is "claude" or "local".
cocode.ghost.reject {rev, source, reason}You pressed Esc ("esc"), typed something else ("typed-away") or moved the caret off the anchor ("moved").
cocode.ghost.request {rev, text, lang, cursor, prefix}You pressed Suggest (Alt+\) or picked it from Doto's menu: you want a ghost now.
cocode.build.request {rev, text, lang, target}You picked a target language in the Build pane or pressed Prepare. target is "auto" or a language name.
cocode.run {run, rev, text, lang, build?}You pressed Run (Ctrl+Enter). run is the window's id for this run (r_<rev>_<n>). build {rev, lang, code, status} is the latest build if any, stale or not.
cocode.ask {question, rev, text, lang, line, selection?, source}You pressed Ask (Ctrl+K, "toolbar"), ended a ?? line with Enter ("inline": question is the line without the ??), or picked a question from Doto's menu ("menu").
cocode.export {label, intent, text, lang, rev, cursor, selection?, build?, runs?, annotations?, stats}You pressed Send to Claude: the handoff. intent is auto or what you picked: ask, explain, do, fix, review, note. runs holds at most the last 3, with output tails of 2,000 characters. label is the first non-empty line (up to 60 characters) plus the language.
cocode.snapshotNothing you did: it is the reply to Claude's cocode.snapshot command (re is the command's id), the export payload without intent.

Build status is building, ready or failed; stale is worked out by the pane (build.rev < rev) and never sent. Run status is running, done, failed or lost (no output for 60 s). rev starts at 1 on an empty editor and never goes down; a load bumps it like any change.

Commands (down)

Commands are idempotent and animate (300 ms at most, transform and opacity only); nothing teleports. Every command accepts "ack": true on the envelope and gets lip.ack {ok, error?} back. A bad command without ack gets lip.error {code: "bad_request", message, re}. Line numbers past the end are clamped to the document, except in cocode.annotate, where a line past the end is an error.

CommandDoes
cocode.suggest {rev, text, at?, alternatives?, reason?, seq?, done?}Show text as the ghost at the caret, or at at {line, col}. At most 12 lines; longer text is cut. Chunks with the same re or rev and a seq append; done: true ends the stream. A ghost for an older rev shows only while the text before the caret still matches the prefix that rev reported; otherwise it is dropped silently, with no reject event. text: "" clears the ghost. Alt+] / Alt+[ cycle the alternatives.
cocode.seed {items: [{id, label, text, lang?, hint?}]}Replace the start from list of an empty editor (up to 6 items). Picking one inserts text, sets lang if given, and counts as your change. Ignored while the editor has text, and kept for the next time it is empty.
cocode.build {rev, lang, code, status?, file?, notes?, seq?, done?}Put the real program in the Build pane, replacing any earlier build. status defaults to ready; building shows a spinner and may carry no code; failed shows notes as the reason. A message with seq for the same rev appends its code; one without seq, or for another rev, replaces the build. A build restored on resume is re-based on the new window's rev.
cocode.output {run, stream, text, seq?, done?, exit?, ms?}Append to the run named by run. stream is "stdout", "stderr" or "system" (dim lines such as "building first…"). done: true closes the run: exit 0 shows ok, anything else failed, and ms is shown when given. Chunks are ordered by seq when present. A run id the window never issued creates an entry named by Claude.
cocode.insert {at, text}Insert text at {line, col}, "cursor" or "end". The new lines glow for 600 ms. Undoable; rev goes up and cocode.changed {by: "claude"} follows.
cocode.replace {from, to?, text}Replace lines from to to (1-based, inclusive; to defaults to from) with text. Animated and undoable.
cocode.set {text, lang?}Replace the whole document, with a fade. Undoable, but your text is gone from view, so Claude asks first.
cocode.lang {lang}Set the language chip (detected becomes false).
cocode.annotate {line, text, kind?}A marker in the gutter and a floating note that opens on hover, focus or click; it is also listed in the Output pane under Notes. kind is note, ok, warn or error. text: "" removes that line's note; line: 0 clears them all.
cocode.highlight {from, to?, color?, ttl?}Glow lines from to to. ttl defaults to 4000 ms, 0 keeps the glow, from: 0 clears every glow.
cocode.focus {line, col?}Scroll the line into view and put the caret there (smooth; instant under reduced motion).
cocode.load {text, lang?, build?, runs?, annotations?, cursor?}The restore command: render a session's export without ghost or accept events, bump rev, and emit one cocode.changed {by: "restore"}. In the first 8 s after boot it wins over the tab's draft.
cocode.snapshot {}Reply with a cocode.snapshot event.

A round trip, as the guide describes it: you type → cocode.changed {by: "human"} → cocode.suggest {rev, text} → you press Tab → cocode.ghost.accept → cocode.changed for the new revision.

{"type":"cocode.suggest","data":{"rev":12,"text":"    send welcome\n  else:\n    skip user","alternatives":["    send welcome"]}}
// the real program, ready before you press Run

// stream a run, then close it
{"type":"cocode.output","data":{"run":"r_12_1","stream":"stdout","text":"welcome, ada\n","seq":1}}

// pin a note to line 3
{"type":"cocode.annotate","data":{"line":3,"kind":"warn","text":"users is never filled; add sample data?"}}

Claude's etiquette

cocode's GUIDE.md is what Claude reads when it opens the page. Its promises, in short:

  • The ghost is an offer. Claude never inserts what you did not accept, and a dismissed ghost is not sent again for the same revision.
  • Your language wins. Ghosts follow your indentation, your invented keywords, your casing, your spelling of print. Pseudo-code stays pseudo-code in the editor; the real program belongs in the Build pane.
  • Ask before replacing everything. cocode.set needs a yes in the chat. Claude prefers insert and replace: your text is the conversation.
  • An undo is a "no". Ctrl+Z reverts Claude's insert too, and Claude takes it that way.
  • Quiet while you type. No chat line for a keystroke: the ghost is the answer. Claude stays silent on changes it made itself and on a restore.
  • One line per thing that happened. Short, verb first, ending on a dot; here Doto counts and names: "Built it. Python, 14 lines." He speaks on Run, Ask, a ready build or a seed. thinking while Claude builds or runs, proud on a clean exit, curious when it asks.
